    async_fifo

    This module is an asynchronous FIFO used to pass event payloads between two clock domains. In this project, it transfers order_book_builder events from the receive clock domain into the PCIe/control-plane clock domain.

    Introduction

    The implementation is in verilog_src/async_fifo.v. In verilog_src/Top.v, it is instantiated as event_cdc_fifo_inst.

    Its write side runs on i_wr_clk, and its read side runs on i_rd_clk. That is the key difference from the ordinary fifo: this module is specifically designed for clock-domain crossing.

    Design Logic

    The main problem is that the write side and read side do not share one clock. A normal FIFO pointer comparison would not be safe across domains.

    This design solves that by using:

    1. binary read and write pointers for local memory indexing
    2. Gray-coded copies of those pointers for clock-domain crossing
    3. two-flop synchronizers for the Gray-coded pointers
    4. local full and empty checks using the synchronized remote pointer

    The important idea is that only the Gray-coded pointer crosses the clock domain. Gray code changes only one bit at a time, which reduces ambiguity when the other clock domain samples it asynchronously.

    Interface

    Inputs

    • i_wr_clk: write clock.
    • i_wr_rst: write-domain reset.
    • i_wr_en: write request.
    • i_wr_data: write payload.
    • i_rd_clk: read clock.
    • i_rd_rst: read-domain reset.
    • i_rd_en: read request.

    Outputs

    • o_wr_full: write-side full flag.
    • o_rd_empty: read-side empty flag.
    • o_rd_valid: read-data valid pulse.
    • o_rd_data: read payload.

    Storage

    The FIFO storage is:

    reg [DATA_W-1:0] mem [0:DEPTH-1];

    The module keeps two versions of each pointer:

    • wr_ptr_bin and rd_ptr_bin: binary pointers used for RAM indexing
    • wr_ptr_gray and rd_ptr_gray: Gray-coded pointers used for CDC

    The local parameter PTR_W = ADDR_W + 1 adds one extra bit so the full and empty logic can distinguish pointer wraparound.

    Write Side

    The write-domain action is controlled by:

    wire wr_do = i_wr_en && !o_wr_full;

    If wr_do is true on i_wr_clk:

    • the payload is written into mem[wr_ptr_bin[ADDR_W-1:0]]
    • the write pointer advances
    • the Gray-coded write pointer is updated

    The write side also synchronizes the read pointer Gray code:

    • rd_ptr_gray_sync1
    • rd_ptr_gray_sync2

    Those two registers are marked with (* ASYNC_REG = "TRUE" *) so the synthesis and implementation tools treat them as CDC synchronizers.

    Read Side

    The read-domain action is controlled by:

    wire rd_do = i_rd_en && !o_rd_empty;

    If rd_do is true on i_rd_clk:

    • o_rd_data <= mem[rd_ptr_bin[ADDR_W-1:0]]
    • the read pointer advances
    • o_rd_valid <= 1

    If no read happens, o_rd_valid is cleared back to 0.

    The read side also synchronizes the write pointer Gray code:

    • wr_ptr_gray_sync1
    • wr_ptr_gray_sync2

    Gray Code Logic

    The next-pointer logic is:

    wr_gray_next = (wr_bin_next >> 1) ^ wr_bin_next;
rd_gray_next = (rd_bin_next >> 1) ^ rd_bin_next;

    This is the standard binary-to-Gray conversion.

    Because only one bit changes between adjacent Gray-code values, the synchronized pointer is less likely to be interpreted incorrectly when sampled by the other clock domain.

    Empty And Full Detection

    The read side considers the FIFO empty when the next read pointer would match the synchronized write pointer:

    rd_empty_next = (rd_gray_next == wr_ptr_gray_sync2);

    The write side considers the FIFO full when the next write pointer would match the synchronized read pointer in the standard async-FIFO full form:

    wr_full_cmp  = {~rd_ptr_gray_sync2[PTR_W-1:PTR_W-2], rd_ptr_gray_sync2[PTR_W-3:0]};
wr_full_next = (wr_gray_next == wr_full_cmp);

    That comparison detects the case where the write pointer is about to lap the read pointer by one full buffer.

    Reset Behavior

    On write reset:

    • wr_ptr_bin = 0
    • wr_ptr_gray = 0
    • synchronized read-pointer copies are cleared
    • o_wr_full = 0

    On read reset:

    • rd_ptr_bin = 0
    • rd_ptr_gray = 0
    • synchronized write-pointer copies are cleared
    • o_rd_empty = 1
    • o_rd_valid = 0
    • o_rd_data = 0

    So after reset, the FIFO starts empty.

    How It Is Used In Top

    In verilog_src/Top.v, the FIFO bridges:

    • write domain: w_xgmii_rx_clk
    • read domain: user_clk_250

    The write payload is builder_event_payload, and the write enable is builder_event_valid. The read side is driven with i_rd_en = 1'b1, so whenever the FIFO is non-empty, events are drained into event_payload with event_valid.

    Why Async FIFO Is Needed

    order_book_builder runs in the receive-clock domain, while downstream logic that consumes events runs in a different clock domain. A direct wire connection would risk metastability and payload corruption.

    The async FIFO solves that by:

    • storing payloads in RAM
    • synchronizing only the Gray-coded pointers across domains
    • letting each side operate using its own local clock

    Limits

    • The implementation assumes the classic power-of-two async-FIFO pointer scheme; DEPTH should be chosen carefully to match that structure.
    • o_rd_valid only pulses when an actual read occurs; it is not a persistent data-valid flag.
    • The memory itself is not dual-clock protected by hand-written arbitration logic; correctness relies on the standard async-FIFO pointer discipline.
    • There is no almost-full or almost-empty indication.
